## 2. 프로젝트 개요

- **프로젝트 명** : Trade Flow 
- **프로젝트 소개** : 관세청 통관자료로 HS 8708 자동차 부품의 수출입 흐름을 품목·상대국·중량 기준으로 비교해, 무역수지가 어디에서 어떻게 바뀌었는지 한눈에 보여주는 대시보드입니다.
- **프로젝트 필요성 (배경)**
  - **완성차 중심 분석의 한계** : 자동차 산업 통계는 대부분 완성차 수출 실적에 맞춰져 있어, 품목마다 경쟁력과 공급망이 다른 부품의 변화를 보기 어렵습니다.
  - **금액 비교의 한계** : 수출액이 늘어도 물량이 늘었다고 볼 수는 없습니다. 가격이나 품목 구성이 달라졌을 수 있어 중량과 단가 대용치를 함께 봐야 합니다.
  - **데이터 활용의 어려움** : 관세청 통계를 조건별로 찾아 비교하려면 시간이 많이 듭니다. 월별 변화, 국가별 비중, 품목별 무역수지를 한곳에서 비교할 화면이 필요합니다.
- **프로젝트 목표**
  - 품목별 무역수지 변화와 흑자·적자 전환 확인
  - 수출 금액과 실제 물량(중량) 비교
  - kg당 금액으로 부품별 평균 단가 대용치 변화 확인
  - 상대국별 수출입 비중 확인
  - 처음 보는 사람도 바로 이해할 수 있는 대시보드 구현

> 현재 대시보드는 저장소의 CSV를 직접 읽습니다. MySQL 적재 코드는 별도 실험용이며 앱 실행에 필요하지 않습니다.

## 3. 데이터 수집 방법

| 데이터셋 | 출처 | 수집 방식 | 적재 테이블 |
| :--- | :--- | :--- | :--- |
| 품목·국가별 수출입 실적 | [관세청 품목별 국가별 수출입실적](https://www.data.go.kr/data/15100475/openapi.do) | OpenAPI | `trades`, `stats` |
| HS 코드와 품목명 | 관세청 HS 코드 참고자료 | 공공데이터 파일 | `parts` |
| 부품 코드 설명 | 관세청 CLIP 세번표 · WCO HS 2022 · 국가법령정보센터 관세율표 · 자동차 부품 HS 표준해석 지침 | 문서 조사 | 화면 상수 |

- **수집 범위** : 2021.11 ~ 2026.09 월별, HS 8708 10단위 코드 25개, 상대국 10개국(US, CN, MX, SK, CZ, IN, UZ, JP, DE, VN). 화면에서 선택할 수 있는 시작 월은 2021.11부터입니다.
- **API 조건** : 월 단위 조회이며 한 요청의 기간은 1년 이내입니다.
- **금액과 중량** : 금액은 달러(수출 FOB, 수입 CIF), 중량은 kg(순중량)입니다.
- **주의** : 관세청이 매월 신고 정정 내용을 반영하므로 최근 달은 바뀔 수 있습니다. 합계는 상대국 10개국의 합이며 한국 전체 수출입이 아닙니다.

**대시보드 데이터 흐름** : 저장소의 CSV → 화면용 변환·집계 → Streamlit. 앱을 실행할 때 외부 API나 DB를 호출하지 않습니다.

| 수집 파일 열 | ERD 열 | 비고 |
| :--- | :--- | :--- |
| `hsNameKor` | `parts.hsKor` | 공식 품명 |
| `statCdCntnKor1` | `stats.statKor` | 국가명. 파일의 `statKor` 열은 품명이므로 쓰지 않습니다. |
| `expWgt`, `impWgt` | `trades.expwgt`, `trades.impwgt` | 대소문자 표기만 다릅니다. |

## 4. DB 설계 (ERD)

![ERD](docs/images/erd.png)

| 테이블 | 설명 | 키 |
| :--- | :--- | :--- |
| `parts` | 부품. HS 10단위 코드, 품목명, 상세설명 | PK: `hsCd` |
| `stats` | 국가. 국가코드, 국가명, 영문 국가명 | PK: `statCd` |
| `trades` | 거래. 월 × 국가 × HS 코드별 수출입 금액·중량·무역수지 | PK: `year` + `statCd` + `hsCd` |

## 5. 주요 기능

> 왼쪽 메뉴에서 페이지를 고릅니다. 네 분석 페이지의 공통 기간은 사이드바에서 선택합니다. 시작 월과 끝 월을 포함해 최대 12개월이며, 선택 범위를 넘기면 끝 월이 시작 월부터 12개월째로 자동 조정됩니다. 페이지별 필터는 각 페이지 제목 아래 한 줄에 표시됩니다. 국가 선택 메뉴와 나라별 비중 그래프에는 국가명과 국기를 함께 표시합니다.

전체 흐름·부품별 무역수지·금액과 중량은 작년 같은 기간과 비교합니다. 나라별 비중은 선택한 기간의 첫 달과 마지막 달 비중 차이를 퍼센트포인트(%p)로 보여줍니다.

### 5-1. 전체 흐름 `views/trend.py`
- 지표 카드 3종 (수출액, 수입액, 무역수지), 작년 같은 기간 대비 변화
- 월별 수출액·수입액 선 그래프, 선택한 기간 음영 표시
- 해마다 같은 기간의 무역수지 막대 그래프
- 페이지 필터 : 대상 국가

### 5-2. 부품별 무역수지 `views/parts.py`
- 월별 그래프를 한 줄에 배치하고 선택 부품 범례는 사이드바에 표시
- 금액 기준은 수출·수입·무역수지, 물량 기준은 수출중량·수입중량 그래프
- 수출·수입 그래프는 같은 y축 범위 사용. 표에는 기간 합계와 작년 동기간 대비 차이·변화율 표시
- 페이지 필터 : 비교할 부품(다중 선택, 전체 부품 합계 포함), 표시 기준(금액·물량)

### 5-3. 나라별 비중 `views/markets.py`
- 수출과 수입의 상대국 비중을 나란히 비교 (10개국 합계 = 100%)
- 선택 기간의 첫 달과 마지막 달 사이 국가별 비중 변화(%p) 그래프와 표
- 페이지 필터 : 부품, 표시 기준(금액·물량)

### 5-4. 금액과 중량 `views/volume.py`
- 지표 카드 3종 (수출액 증감률, 수출중량 증감률, kg당 수출액), 작년 같은 기간 대비 변화
- 선택한 부품의 수출액·수출중량 증감률 막대 그래프와 표
- kg당 금액 증감률 표. kg당 금액은 판매 가격이 아닌 대용치입니다.
- 페이지 필터 : 부품, 상대국

### 5-5. 부품 코드 안내 `views/codes.py`
- 자동차 그림의 위치 표시와 부품별 상세 모달
- 실제 부품 사진 우선 표시, 사진이 없는 경우 생성 이미지 사용
- 여러 부품이 묶인 잔여 코드는 목록을 접어 볼 수 있고, 모달 안에서 사진을 넘길 수 있음

### 5-6. FAQ · 용어 안내 `views/faq.py`
- 수치와 무역 용어, 계산 방법
- HS 코드 읽는 방법
- 화면 필터와 그래프, 데이터 범위 안내

## 6. 실행 방법

### 로컬 실행

Python 3.12와 `uv`가 필요합니다. 대시보드는 저장소에 포함된 CSV를 읽으므로 MySQL 접속 정보나 `.env` 설정 없이 실행할 수 있습니다.

```bash
uv run --python 3.12 --with-requirements requirements.txt streamlit run app.py
```

MySQL 적재 스크립트는 별도 MySQL 실험용입니다. 이 스크립트는 `mysql_streamlit_app`의 테이블을 삭제하고 다시 만들기 때문에, 기존 운영 DB가 아닌 전용 DB에서만 실행하세요.

### Streamlit Community Cloud 배포

1. Streamlit Community Cloud에서 **Create app**을 선택하고 이 저장소와 CSV 로더 코드가 포함된 브랜치를 선택합니다. **Main file path**는 `app.py`입니다.
2. 배포합니다. 대시보드는 `mysql_streamlit_app/database/hs8708_10countries.csv`를 직접 읽으므로 DB 접속 정보나 Streamlit Secrets가 필요하지 않습니다.

화면은 저장소에 포함된 정적 CSV를 사용합니다. 최신 자료를 반영하려면 CSV를 갱신해 저장소에 올려야 합니다. Community Cloud의 Secrets는 DB나 API 등 외부 서비스 인증 정보가 필요한 경우에만 설정합니다. [앱 배포 안내](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)와 [Secrets 안내](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management)를 참고하세요.

## 8. 회고

**최재헌**
> 이 프로젝트에서 기획, 프론트엔드를 서포팅하는 역할을 맡았습니다. 기획 단계에서는 다른 서비스들과의 차별점과 서비스의 활용 가치를 찾아가는데에 중심을 두었고, 직관성 좋은 보드를 만들어보는 것에 초점을 두었습니다.
촉박한 시간과 아직은 어색한 개발 프레임워크 등 어려움이 있었지만, 병결로 인해 불가피하게 참석을 하지 못하게 된 상황에서도 팀원분들이 자신의 맡은 바 이상으로 굉장히 잘 수행해 주셨고, 이를 통해 협업과 팀워크가 무엇인지를 배울 수 있었던 경험이었습니다.

**도연희**
> 프로젝트 기간이 짧아 데이터를 충분히 분석 및 활용하지는 못하고 대시보드 생성까지만 할 수 있었고, 그 점이 살짝 아쉬웠으나 함께 수업을 듣는 학우분들과 협력하여 하나의 결과물을 만들어낼 수 있어서 좋은 경험이 되었습니다. 복잡한 데이터를 처음 보는 사람도 이해할 수 있게끔 시각화하고 배치하는 작업에 집중하였으며, 이를 처음 다루어보는 streamlit이라는 패키지와 바이브코딩을 통해 구현하였습니다. 

**노지훈**
> 수업에서 처음 접하여 익숙하지 않은 SQL과 DB의 개념을 짧은 기간의 프로젝트에 적용하느라 쉽지 않은 작업이었지만, 팀원들의 도움 덕분에 수집한 데이터를 의미있게 전시하는 대시보드를 완성할 수 있었습니다. DB를 설계하여 수집한 데이터를 적재하였고, 실제 데이터와 대시보드가 전시하는 정보의 차이가 없는지 확인하였습니다.

**송건경**
> 본인은 데이터 수집 및 정제 파트로 HS 8708 코드를 중심으로 자동차 완성차가 아닌, 부품의 수출입 현황과 무역수지를 부품별·나라별로 데이터를 모았다. 평소에는 접하기 어려운 관세청 무역 데이터를 직접 모으고 정리해 분석하는 과정이 새롭고 재미있었다. 데이터를 기반으로 흑자가 큰 부품이나 금액과 중량에 따른 관계성을 알수 있는점이 재밌었고, 데이터를 쉬운 화면으로 바꾸는 일의 가치를 느꼈다.

**이용의**
>  해당 프로젝트에서 데이터 정제 및 파이프라인 구축 역할을 맡았습니다. 아직 부족한 지식과 낯설은 작업에 어려움을 겪었지만 팀원들의 도움으로 작업을 마무리할 수 있었습니다. 또한 처음으로 데이터를 다루는 작업에서 재미를 느꼈고, 첫 프로젝트의 좋은 경험을 토대로 공부하여 다음 프로젝트에서 더욱 성장하도록 노력하겠습니다.
